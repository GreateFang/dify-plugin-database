# VexDB Dify 插件

为 **Dify 应用** 提供 **VexDB 向量数据库** 的一站式集成能力，覆盖数据库浏览、表管理、数据写入以及向量相似度检索，适合用于 RAG、语义搜索、Embedding 存储与检索等场景。

---

## 开源说明

本仓库提供 **VexDB Dify 插件** 的完整实现，适合：

* 希望在本地 / 私有环境中部署 Dify + VexDB 的用户
* 希望基于现有能力进行二次开发的开发者
* 希望将 VexDB 向量数据库能力接入 Agent / Workflow 的团队

---

## 插件能力一览

| 能力 | 标识 (ID) | 说明 |
| :--- | :--- | :--- |
| **数据库发现** | `list_databases` | 列出 VexDB 实例中的所有非模板数据库 |
| **表管理** | `list_tables` | 列出 schema 下所有表，支持过滤仅返回含向量字段的表 |
| **表结构感知** | `table_schema` | 获取字段名称、类型、索引等元信息 |
| **数据写入** | `insert_row` | 插入单行数据，支持 JSON 格式及 `floatvector` 类型 |
| **向量检索** | `vector_search` | 基于 `floatvector` 字段进行 TopK 相似度搜索 |

## 详细使用指南 (输入格式规范)

在 Dify 的 Agent 或 Workflow 中编排时，请严格遵守以下参数输入规范，特别是 JSON 数据结构。

### 1. 插入数据 (Insert Row)
向指定表插入一行数据。

* **表名 (`table`)**: 目标表名称（字符串）。
* **行数据 (`row`)**: **⚠️ 必须是合法的 JSON 对象字符串**。
    * 插件内部会使用 JSON 解析器处理此字段，因此属性名必须使用双引号。
    * 向量数据需表示为浮点数数组。
    * **输入示例**:
        ```json
        {
          "content": "这是一个测试文档片段",
          "metadata": {"source": "wiki", "author": "admin"},
          "embedding": [0.012, -0.34, 0.88, 0.15]
        }
        ```
* **Schema**: 默认为 `public`。

### 2. 向量检索 (Vector Search)
执行相似度搜索。

* **表名 (`table`)**: 目标表名称（字符串）。
* **向量列 (`vector_column`)**: 存储向量数据的字段名（如 `embedding`）。
* **查询向量 (`query_vector`)**: **⚠️ 必须是合法的 JSON 数组字符串**。
    * 格式为 `[float, float, ...]`。
    * **LLM 输入示例**:
        ```json
        [0.012, -0.34, 0.88, 0.15]
        ```
* **距离类型 (`distance_type`)**: 可选 `l2` (默认, 欧氏距离), `cosine` (余弦), `ip` (内积)。
* **Top K**: 返回结果数量，默认为 5。

### 3. 获取表结构 (Get Table Schema)
* **表 (`tables`)**:
    * 不填：返回 Schema 下所有表结构。
    * 单表：输入表名，如 `users`。
    * 多表：使用**半角逗号**分隔，如 `users, items`。

### 4. 列出表 (List Tables)
* **仅向量表 (`only_vector_tables`)**: 布尔值 (`true`/`false`)。若设为 `true`，插件会自动过滤掉不包含 `vector` 类型字段的表。

### 5. 列出数据库 (List Databases)
* 列出 VexDB 实例中的所有非模板数据库
* **数据库链接字符串 (`VexDB URI`)**: 数据库链接字符串

## 设计理念

* **弱假设**：不强依赖具体表结构，适合多业务场景
* **即插即用**：授权一次即可使用，必要时支持 `db_uri` 覆盖

---

## 安全与连接说明

* **全局配置**：数据库连接信息通常在安装插件时通过 Dify 的 **Secret Input** 全局配置。
* **临时覆盖**：所有工具均提供 `db_uri` 参数。如果在调用工具时填写此参数，将覆盖全局配置的连接信息（便于调试或多库操作）。
* **隐私安全**：插件代码中对异常进行了捕获，不会在 Tool 返回中直接抛出原始堆栈信息，避免泄露敏感连接串。
